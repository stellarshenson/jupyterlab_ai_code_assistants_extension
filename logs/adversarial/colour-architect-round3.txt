## (b) Defects

- **[MAJOR] A store entry means "pinned colour", not "the user set this" - so the release un-inherits every branch tint on a `derived` provider.** `isVisible`/`_resettableColours` use `!!this._colours.get(id)` as the proxy for "an override exists" (`src/core/panel.ts:1973`, `:1750`), but forks write into the same map: `_inheritColour` passes `colourFor(session)` (`panel.ts:785,955-959`), which for `colourSource: 'derived'` is `userSet || fnv1aColour(id)` and is therefore NEVER null (`src/core/colour.ts:83-91`), and the server does the same on server-copy forks (`core/routes.py:549-556` → `core/colour_store.py:101-104` with `providers/kimi.py:695-696` returning the hash). Failure scenario, Kimi (`derived` + `server-copy`, `providers/kimi.py:695-707`): branch a conversation three times - each fork's tab correctly wears the parent's tint, held by a store entry the user never created. Hand-set a colour on the current conversation, then right-click the row and take `Reset Tab Colours` to undo just that. The click deletes all four entries; the three branches fall back to `fnv1aColour(ownId)` and scatter to three unrelated colours, permanently - acc-crit "Branch colour inheritance" and "Edge: branch of a branch" are broken by an item the user was invited to click, and the acc-crit sentence "shown only while an override exists" is false as written. The leak is pre-existing (the store has always carried two meanings); round-1 exposed it on one conversation and fix 1 widened it to the whole project. Fixes, in cost order: **(i)** record the entry's origin so `_resettableColours` can filter to hand-set ones - the only remedy that keeps both locked criteria, and it costs a store-value format change in `colour_store.py` plus tolerance for today's bare strings; **(ii)** if (i) is judged too expensive, at minimum stop the un-inheriting from being silent - the item must name what it does (`Reset Tab Colours to Default (n)`) and the criterion at `docs/acc-crit-…:249` must say the reset returns every conversation of the project to its OWN default, inheritance included. (ii) is disclosure, not a fix; I would take (i).
- **[MAJOR] The multi-id release fans out N POSTs past the bulk verb that exists for exactly this.** `src/core/panel.ts:932-934` issues one POST per id via `Promise.all(sessionIds.map(id => this._colours.set(id, null)))`, while `ColourStore.forget(ids)` (`src/core/colour.ts:205-224`) already drops a list in ONE request against `DELETE /providers/<id>/colours` → `drop_colours` (`core/routes.py:481-495`, `core/colour_store.py:81-86`), which rewrites the file once. Two mechanisms now exist for "drop these colours", and the only multi-id caller in the frontend picked the non-atomic one. Concrete cost: the server drops the connection after the first of three POSTs and the release is left half-applied - one conversation released, two rolled back, one generic singular error, and the user must click again; the DELETE path has no such state. The single thing blocking reuse is that `forget` returns `void`. Fix: give `forget` the boolean-and-rollback contract `set` just gained (~5 lines, same shape as `colour.ts:194-201`; its two existing callers at `panel.ts:675,1094` ignore a return without a signature break) and call it from `_resetColours`, which then loses `Promise.all`, the `.map`, and `written.some`. Net: one mechanism instead of two, one request instead of N, no partial state.
- **[MINOR] The row's current conversation is derived two different ways in the same class.** `panel.ts:1970` seeds the resettable set from `session.session_id`, while the manage popup twelve lines later uses `this._lastBranchesCurrent || session.session_id` (`panel.ts:1985`) for the same value. `data.branches` excludes `data.current`, so when the project's pin was moved outside this panel within the 30s poll window (`POLL_INTERVAL_MS`, `panel.ts:56`), the true current conversation is in neither the row nor the branch list and an override on it stays unreachable - the exact gap fix 1 exists to close, in a narrower window. Fix: fold `this._lastBranchesCurrent` into the same `hasBranches`-guarded spread at `:1971`. Adds one array element.
- **[MINOR] The only destructive multi-target item in this menu is the only one that hides its count.** `panel.ts:1745-1748` labels 4 conversations as `Reset Tab Colours`; every sibling multi-target item in the same menu carries its number - `Clean Up Parallel Sessions (${n})` `:1756`, `Manage Sessions... The failure copy is singular for a plural action too (`:936`), and reports total failure when one of N writes failed. `docs/acc-crit-…:249` and `ui-tests/tests/colour-override.spec.ts:27` both name only the singular label, so the plural is asserted nowhere (`hasText` substring-matches both).
