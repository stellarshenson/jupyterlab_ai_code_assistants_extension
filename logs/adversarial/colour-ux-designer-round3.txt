## (b) New friction introduced by the round-2 fixes

- **[MAJOR] The plural label hides the blast radius of a destructive, un-undoable action.** `'Reset Tab Colours'` (`src/core/panel.ts:1746-1748`) tells the user that more than one thing changes but not how many, which, or that they belong to conversations the row never displays. Every sibling in this same menu carries its count - `Clean Up Parallel Sessions (N)` (`:1755-1756`), `Switch and Manage Sessions (N)` (`:1934`), `Open Branched Conversation (N)` (`:1948`) - so the one item that omits it is the one whose scope is least guessable. The harm is concrete: distinct colours on two branch terminals is exactly what tab colouring is for, and one click drops both, with no undo and nothing on screen changing for any conversation whose terminal is closed. Fix: `Reset Tab Colours (${this._resettableColours.length})`. Do not add a confirmation dialog - both destructive siblings use one (`:573-579`, `:612-618`) but a modal over a colour reset is over-focusing; the count is the whole fix. Note also that the plural branch is untested at every tier: both Galata cases seed exactly one colour (`ui-tests/tests/colour-override.spec.ts:141`, `:167`), so neither the `> 1` label nor the multi-id `Promise.all` (`src/core/panel.ts:932-934`) is ever exercised.
- **[MAJOR] The whole context menu is now hostage to a network call only one optional item needs.** `panel.ts:1967` awaits a `cache: 'no-store'` GET (`src/core/colour.ts:142-147`) issued through `requestAPI`, which sets no `AbortSignal` and no timeout anywhere (`src/core/request.ts:29-36`). On latency the answer is: **no perceptible delay** - I measured the endpoint on a sandboxed test server at 0.87-2.10 ms over ten samples, three orders below the ~100 ms instantaneous threshold. The defect is the unbounded case, not the median. Before this change a single-conversation row (`extra_sessions === 0`, the common project) opened its menu with zero awaits; now every right-click and both keyboard routes (`panel.ts:1400-1407`, `:1421-1426`) suspend until that GET settles, and against an unresponsive server the menu never appears at all - no cursor change, no spinner, no error - taking Open, Copy Path, Branch and Remove down with it. A slow link also lets two in-flight opens interleave `_rebuildContextMenu` over the shared submenu objects. Fix: `Promise.race` the load against a ~150 ms timer and fall back to the cached map, which the 30 s poll already refreshes (`panel.ts:540`).
- **[MAJOR] The awaited load refreshes the wrong tier, so the release stays invisible for up to 30 s after the gesture.** The server copy is only populated when the terminal reconcile captures the hand-set colour (`src/core/terminals.ts:274-275`, `:319-331`), and that runs on `COLOUR_INTERVAL_MS = 30_000` (`:26`). So in the window right after the user picks a colour on the tab - the single most likely moment to want it back - `_resettableColours` filters to empty (`panel.ts:1973`) and the item is absent while the tab visibly wears the colour; after the capture tick the item appears and the companion's own `Clear` stops sticking. The two affordances swap validity roughly half a minute after the gesture, with nothing on screen naming which regime the user is in, and the natural reading of the missing item is "this feature does not exist". Fix: also count a live companion record when settling the set - `readUserSetTabColour` (`src/core/colour.ts:56-70`) is a synchronous localStorage read costing nothing - for this assistant's open terminals, and for a record-only colour have the reset paint the resolved default through `api.setColour`, since a truthy paint is precisely what releases that record (`node_modules/jupyterlab_colourful_tab_extension/lib/index.js:383-386`).
- **[MINOR] The failure copy stayed singular after the action went plural.** `panel.ts:935-937` fires one message - `'Could not reset the tab colour - try again.'` - for any failure among N writes, so a partial failure reads as a total one, never says how many survived or which, and the banner is wiped by the next successful poll (`:536`). Fix: pluralise off the count of `false` answers in `written`. (This is the count, not NEW-6's error object.)
- **[MINOR] (taste) The label names the surface, not the thing.** The colour is stored and released per conversation (`_resetColours(sessionIds)`, `panel.ts:931`), and for a conversation with no open terminal "Tab Colour" promises something about a tab that is not there. "Reset Conversation Colour" would be truer, but "Tab Colour" matches the gesture the user actually made, so this is defensible either way - taste, no change required.

## Pinned questions

- **Discoverable now that it covers the whole project?** More so, yes - it is reachable from one row for every conversation of that project, which was the round-2 blocker. Not yet reliably: it is absent for up to 30 s after the gesture that creates the need (NEW-b3), and when present it does not say what it will reach (NEW-b1).
- **Does the pluralising label say the right thing?** It says the right *verb* and the wrong *scope*. "Reset" is honest for all three colour sources. The plural is the only signal that more than the row's conversation is affected, and it carries no number in a menu where every other multi-target item does.
- **Is hiding still right under the two new conditions?** Yes, both. The `colouredTabs` gate is correct and correctly initialised at construction, not only on toggle. The non-empty gate is correct in principle; its only miss is the uncaptured-colour window (NEW-b3), which is a freshness bug in the predicate, not an argument against hiding.
- **Perceptible delay on menu open?** No - measured 0.87-2.10 ms, ten samples. The problem is the absent timeout, not the latency.

## What works

- The project-wide set is derived, not guessed: the union of the row's conversation with the branches route's own list, filtered through the store, is exactly the reachable population, and I confirmed against a live server that the branches route excludes the current conversation so both terms are needed.
- The capture/release handshake with the companion extension is sound in both directions - a truthy paint drops the companion's record under the same stable id the panel reads, so the reset is not undone by the reconcile it triggers.
- The `colouredTabs` gate is wired at construction and on change, which is the failure mode this class of fix usually ships with.
- The Galata case for the branch-only release is the right shape: it seeds a colour on a conversation the row does not represent and drives the release by pointer, so row-only keying could not pass it.
