2. **Task [Extended] - Acceptance criteria and architecture decisions** (v0.1.0): Settled the provider-registry architecture and wrote `docs/acc-crit-jupyterlab-ai-code-assistants.md` before any implementation<br>
   **Result**: Surveyed the three assistant extensions to ground the base choice - `jupyterlab_claude_code_extension` v1.2.73 (3041 TS / 2124 py lines) leads `codex` v0.6.12 and `kimi` v0.7.8, and all three carry an identical module shape (`icons`/`index`/`request`/`types`/`widget` over `routes.py`/`sessions.py`) within 40 TS lines of each other, confirming they are forks of one design rather than independent builds. Claude adopted as base. Three decisions taken with the Star Colonel: one consolidated acc-crit doc over per-feature files, since a shared core makes the shared-vs-variant split only legible in one read; live enable/disable of assistants with no JupyterLab reload, matching how the base already applies `presentationMode` live and costing widget teardown, poll-stop, command-removal and tint-clearing logic; and provider modules over a shared Python core (`core/registry.py` dispatching `/providers/<id>/...`) rather than three near-identical route trees. Purpose clarified mid-session as retirement of the standalone extensions, not coexistence, which promoted feature parity, settings and favourites migration, and duplicate-panel conflict detection to first-class criteria. Doc carries 106 criteria across 11 sections including a Galata tier grounded in the `jupyterlab-extension` skill's testing reference - port knob via `JLAB_TEST_PORT`, unconditional `reuseExistingServer: false` (the base uses `!process.env.CI`, unsafe for a suite that drives terminals), serialised workers, redirect-not-`tee` so a dead server reports failure, and a mutation check proving each tier can still go red. Validates clean under `acc-crit.py check`.
