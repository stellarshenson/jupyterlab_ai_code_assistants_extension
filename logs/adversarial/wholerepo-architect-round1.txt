## What is already consistent

- **Core neutrality is enforced, not asserted** - `src/__tests__/core-neutrality.spec.ts` scans `src/core/*.ts` for assistant names outside comments *and* for relative imports into `providers/`; `style/base.css` contains no provider selector either. The claim survives a real fifth-provider test.
- **Both registries fail loudly at the same boundary** - duplicate id raises at registration in TS (`registry.ts:26`) and Python (`registry.py:159`), discovery runs at server start (`routes.py:821`), and a broken module is skipped rather than fatal (`registry.py:151`).
- **The settings schema is generated from the descriptors and self-checks** - `generate-schema.mjs:98-108` refuses a barrel/module count mismatch, so a provider dropped from the barrel cannot ship a settings toggle for a panel that will never appear.
- **Destructive endpoints answer with ids, not counts** - `IDisposalReport` (`types.ts:172`) and the four stores' `remove`/`delete_branches` return exactly what went, so a refused deletion cannot cost a surviving conversation its colour. That discipline is uniform across all four providers.
