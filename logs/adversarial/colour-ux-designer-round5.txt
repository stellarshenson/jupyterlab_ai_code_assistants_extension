## Pinned questions

- **Does `Reset Tab Colour (1)` read correctly to someone who has coloured exactly one tab?** Yes. `isVisible` gates on `length > 0` (`panel.ts:1758`), so `(1)` is the true count of conversations the click will change, and it matches that user's mental model exactly - one tab coloured, one released. The `(1)` earns its place only in the other case, where the single target is a branch whose tab is not open; it does not *disambiguate* the two (both read "1"), but it is never wrong and it matches the sibling convention of stating the number at one. One edge state it cannot cover: a hand-set colour that happens to equal the default the conversation falls back to (a Claude conversation whose `/color` is `sky` and the user hand-picks `sky`) resets to a visually identical tab, and the item then vanishes - correct outcome, zero feedback. I am not filing that; any fix is a new affordance for a rare case.
- **Is "offer nothing when the branch list is unknown" better or worse than offering the row's own conversation alone?** Worse, and strictly so. Under "offer nothing" the releasable set is empty; under "offer the row's own" it is `[session.session_id]`, a superset, and the label states that scope *exactly* - `(1)` is the honest count of what the click deletes, so the round-4 justification ("a scope it cannot state") does not apply to it. The partial outcome it produces - the row released, a branch's hand-set colour left behind - is the same shape as the inherited-tint residue already accepted and documented at acc-crit:271, and it is recoverable on the next open. "Nothing" is not recoverable while the condition persists, and per NEW-2 the condition can persist indefinitely on the provider this feature was built for. My round-4 wording asked for this on a *failed* fetch; applied to a slow one it removes the only exit from a one-way door.
- **Is the fix-6 upgrade behaviour something a user can figure out unaided?** No. What the user perceives is an absence: they read that hand-set colours can now be released, right-click the row whose tab is wearing their hand-set colour, and no such item exists. Absence carries no diagnosis - the available readings are "not shipped yet", "broken", or "not for my assistant", and none of them is "re-pick the colour on the tab". The recovery is also not a gesture anyone performs spontaneously: re-picking the *same* colour you can already see is only meaningful if you know a hidden marker is missing, and it further requires that conversation's terminal to be open. The mechanism itself is right - `panel.ts` aside, `terminals.ts:329-335` gained `&& this._colours.isOverride(observedId)` so re-picking the same colour is no longer swallowed as a no-op, which is what makes the recovery work at all. It needs one sentence in `README.md:36` (NEW-3). The acc-crit entry is a maintainer artefact; no user reads it.

## What works

- The generation token is the right instrument and is applied correctly where it is applied: `_activeSession` moved below the guard (`panel.ts:2028`) with a comment that says exactly why, so the destructive `Remove`/`Copy Path` mis-target is genuinely gone.
- Folding the branch fetch into the same race (`:1997-2002`) reuses the failure mode the code already had rather than inventing a second one - the menu opens without submenus, which is a state the user has always been able to see.
- `Reset Tab Colour (1)` is pinned by `toHaveText`, not `hasText` (`ui-tests/tests/colour-override.spec.ts:182`), so the assertion cannot pass on the plural label - the one place a substring matcher would have hidden a regression.
- Fix 6 chose the asymmetric-cost direction deliberately and wrote the reasoning down at `colour_store.py:44-51`: withholding a release costs one re-pick, offering a wrong one destroys a branch's colour with no undo. That is the correct trade even though it is the one that needs disclosure.

Dimensions passing cleanly, not reported: motion and afterimages (no animation in this diff), focus management (still correctly no modal on the reset), colour fidelity and contrast (unchanged, six companion-owned tokens), keyboard reachability (`panel.ts:1427-1432` routes `ContextMenu` and `Shift+F10` through the same guarded open), desktop/mobile parity (no layout change), visual hierarchy (one menu row among peers, no new salience), output slop in the UI itself (three words plus a count is the right density; the slop in this diff is in the acc-crit prose, not on screen).
