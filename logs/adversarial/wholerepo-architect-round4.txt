## Inconsistencies / defects

- **[MAJOR] `GeminiStore.comm_name` is a boolean marker wearing a wrong value, kept alive by a filter that filters nothing** - `core/routes.py:141-145` builds the `_tree_assistant` candidate list as `[p for p in _enabled_providers().values() if p.store.comm_name]`. All four stores set a non-empty `comm_name` (`claude.py:546`, `codex.py:381`, `gemini.py:427`, `kimi.py:227`), so the filter is the identity function - a guard for a state that cannot occur. It is also the ONLY reader of `GeminiStore.comm_name = "node-MainThread"` (`gemini.py:427`), because Gemini overrides `owns_pid` (`gemini.py:864`) and matches against `_NODE_COMMS = {"node", "MainThread", "node-MainThread"}` (`gemini.py:73`) instead. So the field holds a value that `gemini.py:415-426` itself documents as wrong for Node 24 and earlier - runtime-confirmed on this machine: node v26.6.0 reports `node-MainThread`, node v24.19.0 reports `MainThread` - while `core/store.py:230` and `:366` declare the field to be THE comm and compare it for equality for the other three providers. FACT: I deleted `GeminiStore.comm_name` and collapsed the filter to `list(_enabled_providers().values())` in a `/tmp` copy and the suite stayed green (148 passed, unchanged). The trap is that `_tree_assistant`'s own docstring ("a native binary is its comm") invites the obvious optimisation of pre-filtering by comm equality, which would silently re-break exactly what DEF-24/DEF-10 repaired. **Fix: delete both** - `routes.py:141-145` collapses to `candidates = list(_enabled_providers().values())`, `gemini.py:427` and its 12-line comment go. Costs nothing to remove: `SessionStore.owns_pid` already short-circuits to False on an empty `comm_name` without touching `/proc`. Net -14 lines. (Sub-item, same bullet: `gemini.py:426` says "``owns_pid`` accepts the set below" - `_NODE_COMMS` is at line 73, above the class.)

- **[MINOR] `ForkStrategy` carries a fourth member with no producer and no consumer** - `src/core/types.ts:21-22` declares `'none'`; `src/core/types.ts:86` makes `forkStrategy` REQUIRED, so the justification written above it at `:17-19` ("so a descriptor that omits the flag is legal in both runtimes") describes something TypeScript forbids. No provider sets it, `panel.ts:862/866` never tests for it, and `test_descriptor_parity.py:86` compares runtime values not types. FACT: I removed it in a `/tmp` copy - `tsc --noEmit` exit 0, Jest 82/82. **Fix: delete the member and its three-line comment.** Python's `Capabilities.fork_strategy = "none"` default (`core/registry.py:71`) is likewise set explicitly by all four providers, but that is the dataclass default and is cheap to leave.

- **[MINOR] The colour store is the one core module with a failure path and no logger** - `core/colour_store.py:95` swallows `OSError` and returns False; `ColoursHandler` turns that into a 500 `colour_store_unwritable` (`routes.py:530-540`, `:556-559`). Nothing anywhere records the errno or the path, so the user sees a failed colour and an admin sees a bare `500 POST` in the access log. Every other module with a degrade path has `_log = logging.getLogger(__name__)` - `providers/claude.py:48`, `codex.py:53`, `gemini.py:78`, `kimi.py:51`, `core/migrate.py:30`, `core/registry.py:29`. **Fix: the same two lines here plus `_log.warning("colour store write failed: %s", exc)` in the except.** Adds 3 lines, matches the convention exactly, and is the difference between a diagnosable 500 and an opaque one.

- **[MINOR] `SessionStore.default_colour` advertises a precedence the core stopped implementing** - `core/store.py:399-401` states "Precedence between this and the extension's own colour store is the core's call, off the descriptor's ``colour_source`` flag." `_effective_colour` (`routes.py:198-220`) no longer reads `colour_source` at all - the stored value wins for every provider including `native`, which is the point of the change and is documented correctly two files away in `colour_store.py:1-8` and on the wire handler. `colour_source` survives only in `BranchHandler` (`routes.py:620`). **Fix: delete the last sentence of that docstring.**

- **[MINOR] Half the shared settings defaults got a named home this round; three did not** - `src/index.ts:30` extracts `DEFAULT_SIDEBAR = 'right'`, then `:167` writes `'name'`, `:171` writes `10` and `:176` writes `true` as bare literals at the call sites, while `panel.ts:85` and `:93` already hold `DEFAULT_RECENT_LIMIT = 10` and `DEFAULT_PRESENTATION_MODE = 'name'` that `index.ts` does not import. ## What is already consistent

- **Both destructive routes and `switch` are off the IOLoop now**, with the per-store cost that forced it recorded in the docstring.
